## 0. 제출 전에 꼭 읽을 것

제출 파일은 .tar.gz 형태입니다
하지만 model 폴더를 그냥 .tar.gz로 압축하면 안 됩니다
아래 설명서를 참고해주세요

### 하루 제출 규칙

- 팀당 하루 **3회**까지 제출할 수 있습니다.
- 하루는 **한국 시간 자정**에 초기화되고, **제출한 시각의 날짜**로 셉니다. 밤 11시 59분에 올린 모델은
  대기열 때문에 자정이 지나서 평가가 끝나도 **그날** 횟수입니다.
- 평가가 끝까지 실행된 제출만 셉니다. 파일 문제나 서버 오류로 끝난 제출은 세지 않으니 다시 올려도 됩니다.
- 한 번에 한 건만 올릴 수 있습니다. 앞 제출의 결과가 나와야 다음 모델을 올릴 수 있습니다.

## 1. 제출용 모델 구조 이해하기

### 중요

제출 파일은:

```text
.tar.gz
```

형태로 제출한다.

하지만 학습 모델 prefix 전체를 그대로 압축하면 안 된다.

예를 들어 다음 전체를 제출하는 것이 아니다.

```text
rl-deepracer-sagemaker/
├── ip/
├── metrics/
├── model/
├── output/
├── training-simtrace/
├── reward_function.py
└── training_params.yaml
```

제출에 필요한 것은 `model/` 내부에 있는 실제 모델 파일들이다.

예시:

```text
.ready
.coach_checkpoint

0_Step-0.ckpt.index
0_Step-0.ckpt.meta
0_Step-0.ckpt.data-00000-of-00001

1_Step-xxx.ckpt.index
1_Step-xxx.ckpt.meta
1_Step-xxx.ckpt.data-00000-of-00001

model_metadata.json
deepracer_checkpoints.json

model_0.pb
model_1.pb
model_2.pb
...
```

따라서 MinIO의:

```text
<모델 prefix>/model/
```

내용만 별도의 로컬 폴더로 복사한 뒤 그 폴더를 압축한다.

## 2. 제출 절차 (설명서)

### 2-1. DRfC 폴더로 들어가기

```bash
cd ~/deepracer-for-cloud
```

(deepracer-for-cloud폴더로 들어가기)

### 2-2. 환경 활성화

**사진2**

```bash
source bin/activate.sh
```

(했었다면 또 할 필요 없음)

### 2-3. MinIO에 올라가 있는 모델 목록 확인

**사진3**

```bash
aws $DR_LOCAL_PROFILE_ENDPOINT_URL s3 ls s3://$DR_LOCAL_S3_BUCKET/
```

(사용자마다 이 값은 다를 수 있음)

### 2-4. 제출할 모델 고르기

**사진4**

제출하고자 하는 모델이 있는지 확인하기
(rl-deepracer-sagemaker_new 모델을 올려보겠음)
해당 폴더이름 복사하여 아래에 붙여넣기

### 2-5. 모델 파일을 로컬로 내려받기

**사진5**

```bash
aws s3 sync s3://$DR_LOCAL_S3_BUCKET/여기에제출하고자하는모델폴더이름작성/model/ ./my-model/ $DR_LOCAL_PROFILE_ENDPOINT_URL
```

## 3. 명령어로 다시 정리

### 3-1. 제출할 모델 확인

DRfC 환경 활성화:

```bash
cd ~/deepracer-for-cloud
source bin/activate.sh
```

이미 활성화했다면 `source`는 생략 가능하다.

MinIO 내 모델 목록 확인:

```bash
aws $DR_LOCAL_PROFILE_ENDPOINT_URL s3 ls s3://$DR_LOCAL_S3_BUCKET/
```

예:

```text
PRE custom_files/
PRE rl-deepracer-sagemaker-new2/
PRE rl-deepracer-sagemaker_new/
```

여기에서 제출할 모델 prefix를 선택한다.

예:

```text
rl-deepracer-sagemaker_new
```

### 3-2. 제출할 모델을 로컬 폴더로 복사

예를 들어:

```text
rl-deepracer-sagemaker_new
```

모델을 제출하려면:

```bash
aws s3 sync \
s3://$DR_LOCAL_S3_BUCKET/rl-deepracer-sagemaker_new/model/ \
./my-model/ \
$DR_LOCAL_PROFILE_ENDPOINT_URL
```

정상적으로 실행되면 여러 파일이 다운로드된다.

예:

```text
download: .../.coach_checkpoint
download: .../.ready
download: .../0_Step-0.ckpt.index
download: .../model_metadata.json
download: .../deepracer_checkpoints.json
download: .../model_0.pb
...
```

확인:

```bash
ls
```

다음 폴더가 생성되어야 한다.

```text
my-model
```

내부 확인:

```bash
ls -la my-model
```

### 3-3. 제출용 `.tar.gz` 생성

DRfC 폴더에서:

```bash
tar -zcvf rl-deepracer-sagemaker.tar.gz ./my-model
```

압축 중 다음처럼 모델 파일들이 출력되면 된다.

```text
./my-model/
./my-model/.ready
./my-model/.coach_checkpoint
./my-model/0_Step-0.ckpt.meta
./my-model/0_Step-0.ckpt.index
./my-model/model_metadata.json
./my-model/deepracer_checkpoints.json
./my-model/model_0.pb
...
```

### 3-4. Windows 파일 탐색기에서 압축 파일 확인

Ubuntu 터미널에서:

```bash
explorer.exe .
```

Windows 파일 탐색기가 열린다.

여기서 생성된:

```text
rl-deepracer-sagemaker.tar.gz
```

파일을 확인한다.

## 4. 제출 후 상태

제출 사이트의:

```text
모델 제출
```

메뉴로 이동한다.

파일 선택에서 생성한:

```text
rl-deepracer-sagemaker.tar.gz
```

파일을 선택하고:

```text
제출하기
```

를 누른다.

제출 후 상태는 다음처럼 변경될 수 있다.

```text
queued
→ running
→ done
```

평가가 진행되는 동안에는 새 모델을 제출할 수 없는 경우가 있으므로 현재 제출 결과가 끝날 때까지 기다린다.

### 4-1. 주행 영상과 트랙 이탈 횟수 보기

평가가 끝나면 **모델 제출** 화면 아래쪽 **"직전 평가 주행 영상"** 칸에 다음이 나온다.

- 가장 최근에 평가가 끝난 제출의 **주행 영상**
- 그 주행의 **트랙 이탈 횟수**와 결과(완주 랩타임, 또는 완주 실패 시 어디까지 갔는지와 멈춘 이유)

완주하지 못한 모델도 영상이 남는다. 차가 **어느 구간에서** 트랙을 벗어나는지 보고 보상 함수나
속도 설정을 고칠 때 참고한다.

- 이 영상은 **우리 팀만** 볼 수 있다. 다른 팀에게는 보이지 않는다.
- 리더보드에는 팀별 **최고기록 영상만** 공개된다.
- 새 모델을 올리면, 그 평가가 끝날 때까지는 이전 영상이 그대로 보인다. 평가가 끝나면 새 영상으로 바뀌고
  이전 영상은 지워진다. 계속 보관하고 싶은 영상은 미리 내려받아 둔다.

### 4-2. "업로드 일시 중지" 안내가 보일 때

평가 서버를 점검하는 동안에는 운영진이 업로드를 잠시 막는다. 이때 제출 화면 맨 위에 안내 문구가
뜨고 업로드 버튼이 사라진다. **이미 올려서 대기 중인 제출은 취소되지 않는다.** 점검이 끝나면 순서대로
평가된다. 점검이 끝난 뒤 페이지를 새로고침하면 다시 제출할 수 있다.
